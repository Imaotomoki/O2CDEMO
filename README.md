# O2C 販売管理システム（受注から入金まで）

IBM i で動く、受注 → 出荷 → 請求 → 入金 → 売掛金管理 の一連の業務アプリケーションです。
画面は 5250（DSPF）、帳票はスプール（PRTF）、プログラムは ILE RPG（固定形式）と CL で作られています。

ソースにはライブラリー名を書いていないので、好きな名前のライブラリーに置けます。このドキュメントでは例として `O2CDEMO` を使います。

仕様書（業務フロー・状態遷移・画面ごとのスクリーンショット・ファイル定義など）: [docs/O2C販売管理システム仕様書.xlsx](docs/O2C販売管理システム仕様書.xlsx)

## 使い方

5250 でサインオンし、メニューを呼び出します（メニューは自分が入っているライブラリーをライブラリーリストに追加します）。

```
CALL O2CDEMO/O2CMENU
```

| 番号 | 業務 | プログラム | 画面 / 帳票 |
|---|---|---|---|
| 1 | 受注入力 | `ORDERENTRY` | `ORDENTRYD` |
| 2 | 受注照会・変更・取消 | `ORDMAINT` | `ORDMNTD` |
| 3 | 出荷確定（分納出荷） | `CNFSHPENT` → `CNFSHPCL` → `CONFIRMSHP` | `CNFSHPD` |
| 4 | 在庫入庫・棚卸 | `STKMAINT` | `STKMNTD` |
| 5 | 請求書の照会・印刷・取消（※請求番号は空白でもよい） | `INVINQ`（印刷は `INVPRINT`、取消は `INVCANCEL`） | `INVINQD` / `INVPRTF` |
| 6 | 請求締め（合計請求書） | `BILLCLOSE` | `BILLCLSD` / `CLSPRTF` |
| 7 | 入金処理 | `PAYENTRY` | `PAYENTRYD` |
| 8 | 売掛金年齢表 | `ARAGING` | `ARAGINGD` / `ARAGPRTF` |
| 9 | 督促状発行 | `DUNNING` | `DUNNINGD` / `DUNPRTF` |
| 10 | 入金取消 | `PAYCANCEL` | `PAYCNLD` |
| 11 | 出荷取消 | `SHPCANCEL` | `SHPCNLD` |
| 12 | 在庫照会 | `STKINQ` | `STKINQD` |
| 13 | 売上・入金の月次集計 | `SALESUM` | `SALESUMD` |
| 14 | 顧客の与信・残高照会 | `CUSTINQ` | `CUSTINQD` |
| 15 | データ整合性チェック | `CHKDATA` | `CHKDATAD` |
| 16 | 出荷予定（未出荷の受注） | `SHPDUE` | `SHPDUED` |

F3 でメニューを終了します。

受注日・入金日の初期値と画面右上の日付は、システムの日付（今日）です。日をまたいでサインオンしたままでも、前日の日付にはなりません。

### F4（検索）
手入力しにくいコードは、項目にカーソルを置いて F4 を押すと一覧から選べます（共通の検索ウィンドウ `O2CPRMPT`）。
検索欄にはコードの先頭か名前の一部を入れて Enter。1 を付けて Enter で選択、F12 で取消です。

| 画面 | F4 で選べる項目 |
|---|---|
| メニュー | 請求番号（選ぶと選択が 5=照会 になる） |
| 請求書照会 | 請求番号（選ぶとすぐ照会画面を表示） |

請求書の検索ウィンドウには「絞込」欄があります（空白=取消以外、1=未収、2=期限超過、9=全部）。名称の前に状態（未収・入金済・期限超過・取消）を表示し、顧客コードの前方一致でも検索できます。並びは請求日の新しい順です。

| 受注入力 | 顧客、倉庫、通貨、支払条件、商品（明細） |
| 入金処理 | 顧客、入金方法、通貨 |
| 在庫入庫・棚卸 | 倉庫、商品 |
| 売掛金年齢表 | 顧客 |

通貨（`CURRENCY`）・支払条件（`PAYMENT_TERM`）・入金方法（`PAY_METHOD`）は `CODEMSTRP` に登録されているものだけを受け付けます。呼び出した処理でエラーが起きてもメニューは止まらず、メッセージ行に表示されます（詳細はジョブログ）。

## 業務の流れ

```
受注入力 ──▶ 出荷確定 ──▶ 請求書発行(自動) ──▶ 入金処理 ──▶ 請求締め
 (在庫引当)   (分納可)     CREATEINV/INVPRINT    (消込)       (合計請求書)
                                                     │
                                  売掛金年齢表 ◀──────┴──▶ 督促状発行
```

### 1. 受注入力（ORDERENTRY）
- 顧客・倉庫・商品を入力（F4 で検索）。在庫の引当可能数を超える受注はできません。
- 税率は顧客の税区分（`CODEMSTRP` の `TAX_CAT`）から決まります。
- 与信チェック: 未収残高 ＋ 未出荷の受注額 ＋ 出荷済み未請求額 ＋ 今回の受注額（すべて税込）が、与信限度額を超えるとエラーです（限度額 0 は無制限）。
- 取引停止の顧客、販売停止の商品は受注できません。
- 単価: 空白なら商品の標準単価。円は整数、外貨は小数 2 桁まで入力できます（カンマ可。例 `12.50`、`4,800`）。数字以外や桁の多すぎる入力はエラーになり、入力した文字のまま再表示します。
- 在庫引当・受注・明細はコミットメント制御で一括確定します（途中で失敗したら全て取り消し）。

### 2. 受注照会・変更・取消（ORDMAINT）
- 一覧は新しい順。「顧客」（前方一致、F4 で検索）と「状態」（空白=全部、1=未完了、2=完了＝請求済・取消）で絞り込み、Enter で検索します。
- 5=照会、2=変更（受注数の増減。増加は追加引当、減少は引当を戻す。出荷済数より少なくはできない）、4=取消（未出荷の受注だけ。引当を全て戻す）。

### 3. 出荷確定（CNFSHPENT）
- 1=出荷確定（全量）、2=分納出荷（ウィンドウの「今回出荷」欄に明細ごとの出荷数を入力して Enter。F12 で出荷せずに戻る）。
- 出荷確定と同時に請求書を作成し（`CREATEINV`）、請求書を印刷します（`INVPRINT`、スプール `INVPRTF`）。
- 分納では出荷のたびに請求書を作ります。全量出荷が済むと受注は「請求済」になります。

### 11. 出荷取消（SHPCANCEL）
- 出荷の一覧（出荷日の新しい順。顧客コードで絞り込み、F4 で顧客検索）で 4 を付けて Enter → 確認画面で在庫に戻す商品と数量を確認 → F6 で取消。
- 取り消せるのは未請求の出荷だけです。請求済の出荷は、先に請求書照会の F10 で請求書を取り消してください。
- 出荷を「取消済」にし、在庫の現在庫と引当済を出荷数だけ戻し（引当し直すので有効在庫は変わりません）、受注明細の出荷済数を減らして受注を引当済／一部出荷に戻します。在庫移動履歴（`STKMOVEP`）に `SHPCANCEL` を記録します。
- 戻った受注は出荷確定の一覧にまた出るので、出荷し直せます。取消済の出荷は請求されません。

### 4. 在庫入庫・棚卸（STKMAINT）
- 倉庫コード（例 `WH-TOKYO`）と処理（1=入庫 / 2=棚卸）を入力します。
- 入庫: 商品コードと数量を入力 → Enter で確認 → F6 で登録。商品コードを変えた直後の F6 は確認表示だけになります（別商品への誤入庫防止）。倉庫に在庫レコードがない商品は新しく作ります。
- 棚卸: 倉庫の在庫一覧で実棚数を入力 → Enter で差異を確認 → F6 で反映。引当済数より少なくはできません。表示した後に他の処理で在庫が変わった場合は反映せず、一覧を再表示します。
- 増減は在庫移動履歴 `STKMOVEP` に記録します（区分 `RECEIPT` / `COUNT`）。

### 5〜7・10. 請求・入金
- **請求書の照会（INVINQ）**: メニューで 5（「※請求番号」に入力しておけばすぐ表示。空白なら入力画面で請求番号を入力するか F4 で一覧から選ぶ）。
  見出し（状態・顧客・請求日・支払期限・通貨）、明細、税率別の対象額と消費税額、小計・消費税・請求合計、入金済・未収残高を表示します。未収があって支払期限を過ぎていれば日数を赤で表示します。円は小数なし、外貨は小数 2 桁です。
  F6 で請求書を印刷します（`INVPRINT`、スプール `INVPRTF`）。外貨の請求書は小数 2 桁、税率 0% も 0 と印字します。
  F7 で入金履歴（`INVPAYH`）: どの入金でいくら消し込んだかを一覧します。入金取消で戻した消込はマイナス・区分「取消」で出ます。
- **請求書の取消（照会画面の F10）**: F10 を 2 回押すと取り消します（`INVCANCEL`）。状態を「取消済」・残高を 0 にし、請求した出荷と受注を未請求（出荷済）に戻します。
  - 取り消せるのは入金済が 0 の請求書だけです（入金があるときは先に 10=入金取消）。締め済みの期間の請求書は取り消せません。
  - 取消済の請求書は売掛金年齢表・督促・入金・締め請求の対象から外れ、印刷もできません。
  - **作り直し（F11）**: 取消済の請求書で F11 を押すと、未請求に戻した出荷から請求書を作り直して印刷します（`CRTINVCL` → `CREATEINV`。単価・数量は受注のもの）。
- **入金処理（PAYENTRY）**: 顧客・入金日・入金方法・通貨・金額を入力 → 未収の請求書一覧で消込先に 1 を付ける（付けなければ古い順）→ F6 で確認 → Enter で登録。
  消込は請求書の通貨で行います。一覧には入金と同じ通貨の請求書だけが出て、入金額（換算前）で消し込みます。円換算額（入金日の為替レート）は入金の記録に残します。
- **入金取消（PAYCANCEL）**: 入金の一覧（新しい順。顧客コードで絞り込み、F4 で顧客検索）で 4 を付けて Enter → 確認画面で消込を戻す請求書と取消後の残高を確認 → F6 で取消。
  - 入金の状態を `CANCELLED`（取消済）にし、消し込んだ請求書の入金済を減らして残高を戻します（入金済が 0 なら未入金、残れば一部入金）。
  - 消込明細（`PAYAPPLYP`）は消さず、マイナスの明細を追加して履歴を残します。全体を 1 つのトランザクションで行い、途中で失敗したら元に戻します。
  - 締め済みの期間（入金日が顧客の最終締め日以前）の入金は、合計請求書の御入金額が変わるため取り消せません。
- **請求締め（BILLCLOSE）**: 締め日を入力すると、その日が締日の顧客が「対象」になります。1=締め実行で合計請求書を発行します（スプール `CLSPRTF`）。
  - 締日は一覧の「締日」欄を書き換えて Enter で保存します（`CUSTCLSP`。未設定・0 は末日締め）。
  - 今回御請求額 ＝ 前回御請求額 − 御入金額 ＋ 今回お買上額 ＋ 消費税額
  - 締め済みの顧客に 1 を付けると、記録済みの内容で再発行します。
  - 未来の日付、同じ締め日以降に締めがある顧客は締められません。
  - 合計請求書は顧客の通貨（`CUSTOMERP.CURRCD`）で作ります。集計するのはその通貨の請求書と入金（換算前の金額）です。外貨は小数 2 桁と通貨コードを印字します。

### 8〜9. 売掛金管理
- **売掛金年齢表（ARAGING）**: 基準日時点の未収残高（外貨は円換算）を、支払期限からの経過日数で「期限内 / 1-30日 / 31-60日 / 61-90日 / 91日超」に分けて顧客別に表示します。5=請求書明細、F6=印刷（スプール `ARAGPRTF`、構成比つき）。
- **督促状発行（DUNNING）**: 支払期限を指定日数以上過ぎた未収がある顧客を一覧し、1=督促状発行（スプール `DUNPRTF`）。回数に応じて「お支払いのお願い」→「（再通知）」→「（最終通知）」と文面が変わります。一覧の金額は円換算、督促状は請求書の通貨（通貨ごとに合計）で印字します。履歴は `DUNNINGP`。同じ基準日の再発行は回数を増やしません。

### 12〜14. 照会・集計（メニュー右の列）
- **在庫照会（STKINQ）**: 倉庫コード・商品コード（前方一致、F4 で検索）で絞り込み、倉庫×商品ごとに現在庫・引当済・有効在庫を表示します（有効在庫 0 以下は赤）。5=入出庫の履歴: 在庫移動履歴（入庫・棚卸・出荷取消）と出荷を日付の新しい順に表示します（取り消した出荷は「出荷*」）。
- **売上・入金の月次集計（SALESUM）**: 終了年月（YYYYMM）までの 12 か月の請求件数・売上（税抜）・消費税・請求合計・入金額を月ごとに表示します（取消済の請求書・入金は除く）。外貨の請求書は請求日の為替レートで円換算、入金は入金時の円換算額です。5=その月の顧客別の内訳。
- **顧客の与信・残高照会（CUSTINQ）**: 顧客ごとに与信限度額・与信使用額（未収残高＋未出荷の受注＋出荷済未請求。受注入力の与信チェックと同じ式）・残り与信・最も長い期限超過日数を表示します（金額は顧客の通貨、一覧は小数なし）。超過は赤。5=詳細（内訳・未収件数・最後の入金日）。

- **出荷予定（SHPDUE、16）**: 未出荷の受注明細（引当済・一部出荷の受注で残数 > 0）を希望納期の早い順に表示します。倉庫で絞り込み（F4 で検索）。納期を過ぎた行は希望納期と遅れ日数を赤、倉庫の現在庫が残数より少ない行は現在庫を赤で表示し、件数を見出しに出します。

### 15. データ整合性チェック（CHKDATA）
- 次の 10 項目を点検し、合わないものを「値（いまの値）」と「あるべき値（ほかのファイルから計算した値）」で一覧します。データは変更しません。F5 で再実行。
  1. 請求書の入金済 ＝ 消込明細の合計　2. 残高 ＝ 合計 − 入金済　3. 取消済の残高 ＝ 0　4. 合計 ＝ 小計 ＋ 税　5. 状態と入金済・残高の組み合わせ
  6. 受注明細の出荷済数 ＝ 取消以外の出荷の合計　7. 有効在庫 ＝ 現在庫 − 引当済　8. 引当済 ＝ 取消以外の受注の未出荷数の合計　9. 入金額 ＝ 消込の合計（取消以外）　10. 受注の合計 ＝ 明細の合計
- 受注照会・変更（2）では、変更モードで単価も変更できます（円は整数、外貨は小数 2 桁まで）。請求済の出荷がある受注は単価を変えられません。単価を間違えた請求書は「請求書照会で F10（取消）→ 受注照会で単価を変更 → 請求書照会で F11（作り直し）」の順で直します。請求書を取り消して出荷済に戻った受注も変更できます。

## 通貨（外貨）の扱い

| 処理 | 金額の通貨 |
|---|---|
| 受注・出荷・請求書 | 受注の通貨 |
| 入金の消込 | 請求書の通貨（入金と同じ通貨の請求書だけを消し込む）。円換算額は入金の記録用 |
| 売掛金年齢表、督促の一覧・履歴 | 円換算（基準日以前の直近の為替レート。なければ最も古いレート） |
| 督促状、合計請求書 | 請求書・顧客の通貨（外貨は小数 2 桁と通貨コード） |
| 請求書の照会・印刷 | 請求書の通貨（外貨は小数 2 桁） |

為替レート（`FXRATEP`）が 1 件もない外貨の請求書は、年齢表・督促の一覧で 0 円として集計し、件数を画面に表示します。

番号の形式: 受注 `SO-…`、出荷 `SHP-n`、請求 `INV-n`、入金 `PAY-n`。
シーケンスはキャッシュするため、番号が飛ぶことがあります（例 `PAY-1` の次が `PAY-21`）。

## 新しい環境へのセットアップ

ライブラリー名を `O2CDEMO` にする例です。別の名前にするときは `O2CDEMO` を置き換えてください。セットアップ用の CL（`CRTFILES` `SETUPJRN` `COMPINIT` `INITDATA` `COMPBIZ`）は、ライブラリー名をパラメーターで受け取ります。

1. ライブラリーとソースファイルを作り、このリポジトリーのフォルダー（`QRPGLESRC` / `QCLLESRC` / `QDDSSRC`）のファイルを、同じ名前のソースファイルのメンバーとして置く（メンバー名＝ファイル名、ソースタイプ＝拡張子）
   ```
   CRTLIB     LIB(O2CDEMO)
   CRTSRCPF   FILE(O2CDEMO/QRPGLESRC) RCDLEN(92) CCSID(1399)
   CRTSRCPF   FILE(O2CDEMO/QCLLESRC)  RCDLEN(92) CCSID(1399)
   CRTSRCPF   FILE(O2CDEMO/QDDSSRC)   RCDLEN(92) CCSID(1399)
   ```
2. データベースを作る — 物理ファイル・論理ファイル・SQL シーケンス
   ```
   CRTBNDCL   PGM(O2CDEMO/CRTFILES) SRCFILE(O2CDEMO/QCLLESRC)
   CALL       PGM(O2CDEMO/CRTFILES) PARM('O2CDEMO')
   ```
3. ジャーナルを設定する — ジャーナル `O2CJRN` を作り、ファイルの記録を開始（コミットメント制御に必要）
   ```
   CRTBNDCL   PGM(O2CDEMO/SETUPJRN) SRCFILE(O2CDEMO/QCLLESRC)
   CALL       PGM(O2CDEMO/SETUPJRN) PARM('O2CDEMO')
   ```
4. 初期データ（サンプルのマスター）を入れる
   ```
   CRTBNDCL   PGM(O2CDEMO/COMPINIT) SRCFILE(O2CDEMO/QCLLESRC)
   CALL       PGM(O2CDEMO/COMPINIT) PARM('O2CDEMO')
   CALL       PGM(O2CDEMO/INITDATA) PARM('O2CDEMO')
   ```
5. 業務プログラムをすべてコンパイルする — 画面・帳票 → RPG → CL の順にコンパイルし、在庫トリガーを設定（業務画面を閉じた状態で。バッチ投入がおすすめ）
   ```
   CRTBNDCL   PGM(O2CDEMO/COMPBIZ) SRCFILE(O2CDEMO/QCLLESRC)
   SBMJOB     CMD(CALL PGM(O2CDEMO/COMPBIZ) PARM('O2CDEMO')) JOB(COMPBIZ)
   ```
6. メニューを呼ぶ: `CALL O2CDEMO/O2CMENU`

| ソースタイプ | コンパイル |
|---|---|
| `SQLRPGLE`（`ARAGING` `BILLCLOSE` `DUNNING` `STKMAINT` `CREATEINV` `CREATESORD` `CONFIRMSHP` `INVTRIGGER` `ORDERENTRY` `PAYENTRY`） | `CRTSQLRPGI OBJTYPE(*PGM) CLOSQLCSR(*ENDMOD)` |
| `RPGLE`（`CNFSHPENT` `ORDMAINT` `INVPRINT` `INVINQ` ほか初期データ投入） | `CRTBNDRPG` |
| `CLLE`（`O2CMENU` `CNFSHPCL` `CRTINVCL` ほか） | `CRTBNDCL` |
| `DSPF` / `PRTF` | `CRTDSPF` / `CRTPRTF` |

`COMPBIZ` が使うコマンドは次のとおりです（1 本ずつ手でコンパイルするときも同じ）。

## 開発時の注意

- **既存のソースメンバーの更新は、ソース日付（SRCDAT）を保つ手順で行う**。`CPYFRMSTMF` や SQL でメンバーを書き換えると、ソース日付が消える。
- ライブラリー名はソースに書かない。プログラムはライブラリーリストから探し、メニューは呼び出しスタック（`QWVRCSTK`）から自分のライブラリーを調べて追加する。
- ソースは 1 行 80 バイト（CCSID 1399）。全角は前後に SO/SI の 2 バイトが付く。
- DDS で全角の定数の直後に項目を置くときは 1 桁空ける。SI と次の項目の属性バイトが重なると、項目が表示されない（コンパイル時の警告 `CPD7866`）。
- F6 などで画面の入力（サブファイルの選択など）を受け取るキーは `CF` で定義する（`CA` は入力を返さない）。
- 'A' 型（CCSID 5123）の列には全角を入れられない（SQLCODE -330）。全角を入れる列は 'O' 型にする。
- 日付はシステムの日付を使う。RPG は `%DATE()`、DDS は `DATE(*SYS)`。`*DATE`・`UDATE`・`DATE(*JOB)` はジョブの日付で、サインオンした日のまま日をまたいでも変わらない。
- 画面を開いたままの 5250 セッションがあると、その画面（DSPF）を作り直せない（`CPF2143` 割り振りできない）。メニューは F3 で終わっても画面を開いたままにするので、作り直す前にそのセッションで `RCLRSC` を実行するかサインオフする。
- 全角の文字列を `+` で連結すると間に SI/SO が残るため、各プログラムの `Join` 手続きで取り除いている。
